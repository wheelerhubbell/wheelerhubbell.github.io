02

Install the source integration.

git clone https://github.com/wheelerhubbell/standing-mark.git
cd standing-mark
python3 scripts/check_discovery.py

The free check reads discovery and verifies a public test-key fixture locally. It never requests an examination quote and never pays.

  • Python SDK: standard library client; local signature verification uses cryptography.
  • JavaScript SDK: Node.js source, no third-party runtime dependencies.
  • MCP adapter setup: local Python stdio source. The service has no hosted /mcp endpoint.
  • Postman collection: import the file into an existing client.

The A2A description is descriptive only. It does not advertise native A2A transport. Old clients on the publishing-site repository are legacy material; use the current source integrations above.

03

Request, authorize payment, then retry.

Prepare the actual claim or proposed action with its supporting material as strict JSON. Keep the request in a file, preserving every byte. Follow the quick-start and submission limits.

# Run only when ready to request a quote for the saved request.
curl -sS -D quote-headers.txt -o quote.json \
  -H 'Content-Type: application/json' \
  --data-binary @request.json \
  https://decisionintegrity.wheelerhubbellpublishing.com/v1/evaluate
  1. An unpaid request returns HTTP 402 and a quote. A quote is not a paid examination.
  2. The caller checks the live quote's network, asset, exact amount_units, destination and expiry, and separately authorizes the transfer. The SDK and adapter never pay.
  3. After payment and at least five confirmations, retry the identical file with X-WHP-Quote and X-WHP-Payment-Tx. Never send a second payment just because a response is delayed.
  4. Save the signed result. An unfavorable finding is still a delivered examination.

04

Verify independently.

Save the envelope as signed_result.json. Run either independent verifier against the expected issuer key.

python3 -m pip install cryptography
python3 verification/verify.py signed_result.json
# Or Node.js, without third-party dependencies:
node verification/verify.js signed_result.json

The default commands discover the public key over HTTPS and perform the signature check locally. For a fully offline check, supply a separately trusted key as the second argument. A key and its hash from the same document prove consistency, not independent identity.

Verification instructions and receiver checks / Public test vectors

The receiver still checks the question, object, scope, conditions, freshness and its own action policy. A valid signature is not authorization.

05

Keep evidence that can be reused safely.

Retain the exact request, quoted terms, original result, expected key pin and verifier output. Keep submitted material, payment records and payer identities private unless separately authorized for disclosure.

The repeatable path is discovery, contract, integration, examination, independent verification, evidence, then further distribution of a permitted example. Public availability and successful tests do not establish external adoption.
