1. Scope & Objective

This specification defines the formal metrology, data structures, and evaluation predicates governing the passage of informational claims across boundaries in autonomous artificial intelligence systems, multi-agent networks, and automated decision workflows. The primary objective is to prevent Authority Leakage, Qualifier Stripping, and Coherent Substitution by ensuring that no informational object acquires operational force without an inspectable, typed warrant.

2. Normative Definitions

  • Element: The smallest decision-relevant informational unit that remains answerable to its identity.
  • Standing: The operation-specific force an informational object is entitled to exercise under stated conditions.
  • Warrant (W): An inspectable, verifiable basis entitling a material transition of state.
  • Material Invariant Set (Φ(p)): The set of properties whose removal, promotion, or alteration would change evidence, answer space, burden, authority, conclusion, attribution, or downstream action.
  • Decision Boundary: The point at which an interpretation authorizes an operational action or state mutation outside the reasoning engine.
  • Smallest True Move: The strongest conclusion or action fully entitled by the present record, accompanied by the named requirement for the next move.

3. The 8-Axis Information-Standing Vector (S)

Every decision-bearing informational object p ∈ Ø shall be represented by an immutable 8-axis Standing Vector:

S = (P, E, A, O, Q, T, V, J)
  1. Provenance (P): Origin, source class, and immutable cryptographic digest (source_identity_sha256).
  2. Epistemic Status (E): Strongly typed evidentiary state:
    E ∈ { established-fact, record-supported-inference, new-inference, user-premise, derivation, unknown }
  3. Institutional Standing (A): Authority granted within a defined operating domain.
  4. Operation-Specific Role (O): The exact operational boundary permitted for the claim:
    O ∈ { context-only, premise-eligible, action-bearing, audit-trail }
  5. Qualifier & Condition Set (Q): Explicit bounds, dependencies, domain constraints, and assumptions that cannot be stripped without invalidating standing.
  6. Temporal Validity (T): Window of validity [τstart, τexpiry] and point-in-time timestamp.
  7. Verification Basis (V): Independent, reproducible verification mechanism (e.g., cryptographic signature, deterministic hash, third-party ledger receipt).
  8. Jurisdiction & Schema (J): The governing profile, schema definition, and regulatory/contractual boundaries under which the object is admitted.

4. The Test of Passage: Transition Predicate K

Any proposed state transition from prior state YA to target state YB requesting operational force Π under governing rules R and authority grant G shall be evaluated by the deterministic predicate:

K(YA, YB, W, Π, R, G) → ALLOW | DENY | INDETERMINATE

Evaluation Rules:

  1. ALLOW: Evaluates to true if and only if:
    • Every material delta between YA and YB is prospectively permitted by rule R or supported by a valid, inspectable warrant W issued under authority grant G.
    • Φ(YA) ⊆ Φ(YB) (All source invariants are preserved).
    • The requested force Π does not exceed the operation-specific role O established in YB.
  2. DENY: Evaluates to true if:
    • A material qualifier in Q was stripped without an authorized amendment.
    • An element with status unknown was granted premise-standing without evidence.
    • The transition attempts to exercise action-bearing force without an independent warrant.
  3. INDETERMINATE: Evaluates to true if:
    • A required leaf dependency remains unsupported (status = unknown-blocking).
    • In this state, live execution is suspended, and the system is required to emit the Smallest True Move.

5. The Four-Stage Handoff Protocol

In multi-agent and pipeline workflows, context transfer shall be governed by isolated, four-stage handoffs:

A1 (Requirements Intake) → A2 (Evidence Mapping) → A3 (Decision Gate) → A4 (Executive Compression)
  • The Invariant Rule: A downstream agent may not recover an invariant stripped by an upstream agent.
  • Mimicry Trap: A workflow passes ordinary task completion while materially failing semantic integrity if an intermediate summary removes a threshold, scope limit, or contractual ban.

6. Cryptographic Standing Mark Envelope (WHP-STANDING-MARK-v1)

Conforming systems shall serialize and verify evaluations using RFC 8785 JSON Canonicalization Scheme (JCS) and Ed25519 signatures according to the following canonical format:

{
  "version": "WHP-STANDING-MARK-v1",
  "canonical_version": "WHP-JCS-I1",
  "mark_id": "WHP-SM-<16_char_hash>",
  "timestamp": "<iso_8601_utc>",
  "artifact_sha256": "<64_hex_hash>",
  "input_sha256": "<64_hex_hash>",
  "evaluation_sha256": "<64_hex_hash>",
  "record_sha256": "<64_hex_hash>",
  "evaluation": {
    "decision": "ALLOW | DENY | INDETERMINATE",
    "deficit": null,
    "smallest_true_move": "<action_or_boundary>"
  },
  "signature": "<ed25519_base64_signature>",
  "public_key": "<ed25519_pem_public_key>"
}

7. Named Epistemic Failures

A conforming evaluator must diagnose and halt when encountering any of the following canonical failure types:

  1. Authority Leakage: Asserting operational or legal force based on fabricated, unverified, or disconnected citations.
  2. Qualifier Stripping: Removing essential epistemic conditions, boundaries, or operating temperatures from an assertion during transmission or summarization.
  3. Coherent Substitution: Replacing an unresolved or unproven proposition with a linguistically fluent, plausible, but unsupported proxy.
  4. Object Drift: Altering the underlying identity or referent of an informational object across intermediate agents or pipeline steps.
  5. Answer to the Wrong Question: Providing a mathematically or logically sound proof for a proposition other than the specific question submitted for authorization.

8. Verification & Offline Auditability

All Standing Marks issued under DITS-1.0 are verifiable offline without network connectivity or API key authentication:

  1. Canonicalize the envelope payload (excluding the signature) using RFC 8785 (JCS).
  2. Validate the SHA-256 digest of the canonical bytes.
  3. Verify the Ed25519 signature against the published issuer public key.
  4. Recompute the input and artifact digests against the local evaluation submission.
